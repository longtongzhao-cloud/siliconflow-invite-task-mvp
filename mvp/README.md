# 邀新任务台 MVP

这是技术验证后的第一阶段可运行 MVP，覆盖人工核对淘宝付款到人工奖励的本地业务闭环。第一阶段不调用淘宝 API：运营人员确认付款后人工建单并发送客户链接；本地演示使用不会联网的 SiliconFlow 适配器。

完整的管理员、客户和抢单人操作步骤见 `USER_GUIDE.md`。

## 当前阶段结论

- 自有核心通过：SKU 容量、N 人限额、30 分钟保护、15 分钟提醒、24 小时截止、超时补做、奖励锁定和人工支付幂等。
- 本地代理登录闭环通过：手机号、演示 OTP、合成会话、AES-256-GCM 密文保存、邀请码返回和 24 小时销毁边界。
- 外部接入待现场验证：真实 SiliconFlow 登录和邀请记录读取没有在本 MVP 中发起调用；淘宝订单 API 与聊天自动发送已经明确延期。
- 自动化验收：44 项配置、API、权限、并发、安全与生命周期测试全部通过。

## 环境配置

配置由 `mvp_app/config.py` 集中加载和校验。开发模板见 `.env.example`；生产变量清单见 `.env.production.example`。模板只用于说明，应用不会自动把模板加载为环境变量，部署时应通过服务管理器或密钥管理服务注入真实值。

当 `MVP_ENV=production` 时，应用会在启动阶段拒绝以下配置：缺失、过短或仍为示例占位值的密钥；`mock` SiliconFlow；`mock` 本站短信；演示数据初始化。当前尚无真实短信适配器，因此生产模板把 `MVP_SITE_SMS_MODE` 设为 `disabled`，本站发送和校验验证码接口会返回 503。真实短信接通前，生产环境不能完成抢单人手机号登录。

手机远程浏览器入口由 `MVP_REMOTE_BROWSER_MODE` 控制，当前唯一允许值为 `disabled`。API、数据表和前端状态已经预留，但真实 Chromium、一次性 viewer、WebRTC/noVNC 网关和受信回调尚未实现；点击能力不会回退到验证码代收或私有接口调用。

下一阶段网关的状态机、接口和安全验收门槛见 `REMOTE_BROWSER_GATEWAY.md`。

## 核心流程

1. 运营人员在淘宝或千牛人工确认客户已经付款。
2. 管理员进入“订单管理”，人工录入淘宝订单号、SKU 和数量，生成客户专属链接。
3. 管理员复制客户链接，通过淘宝聊天人工发送给对应客户。
4. 客户打开链接，点击“开始 SiliconFlow 登录”；本地环境运行 mock 演示，真实网关未启用时可手动填写邀请码。
5. 任务开放后，将任务链接发送到微信群等渠道。
6. 抢单人完成本站手机号登录和支付宝收款信息登记，再领取名额。
7. 领取成功后才向该抢单人显示官方邀请链接；抢单人在手机完成注册和实名后，回填 SiliconFlow 用户 ID。
8. 用户 ID 只作为待核验声明，不直接触发奖励；本地演示可模拟状态，人工模式由管理员对照官方记录确认。
9. 成功者生成 5 元待支付奖励，管理员转账后登记唯一支付宝流水号。

## 关键规则

- `target_n` 只能由 `SF_INVITE_1/5/10 × 购买数量` 计算。
- 数据库事务始终保持 `reward_locked + active_reservations <= target_n`。
- 保护期按服务端时间计算，恰好到 30 分钟视为超时。
- 超时用户在订单 24 小时内补做，只有仍有未保护容量时才能锁定奖励。
- 支付失败或待支付仍占用已锁奖励，不能释放给第 N+1 人。
- 同一本站账号、支付宝账号和上游用户键只能获得一次奖励。
- 公开任务接口不会在抢单前返回邀请码或邀请链接，避免绕过 N 人名额。

## 数据安全

- 手机号只保存 HMAC 索引和掩码，不保存明文。
- 支付宝账号、姓名和 SiliconFlow 会话采用 AES-256-GCM 应用层加密。
- SiliconFlow OTP 仅在单次请求内使用，不进入数据库。
- 会话 AAD 绑定订单、用户引用、记录 ID 和到期时间，最长 24 小时。
- 真实生产密钥必须迁移到独立 KMS；本地环境变量方案只用于 MVP。

## 适配器模式

- `mock`：仅本地演示，不联网；完整模拟代理登录和状态变化。
- `manual`：客户手动填写邀请码，管理员人工确认邀请记录。
- `live-disabled`：真实 SiliconFlow 调用失败关闭；不能靠前端或普通运行时开关启用。

未来取得稳定接口与接入条件后，应新增独立的 live 适配器部署，并保留字段漂移熔断、401/403 熔断和人工审核降级。
