# 邀新任务台 MVP 使用说明

最后核对日期：2026-08-16  
适用版本：当前本地 MVP

## 使用边界

当前版本用于本地演示、业务规则验收和后续接口联调，不可直接用于生产经营。

- SiliconFlow 真实登录、邀请码读取、注册和实名认证状态查询尚未接通。
- 淘宝订单同步、店铺授权、消息订阅及聊天自动发送尚未接通。
- 本站手机号登录使用开发验证码，不会发送真实短信。
- 支付宝奖励由管理员线下转账，系统只登记支付结果，不会自动付款。
- 本地服务默认只允许本机访问，没有公网 HTTPS、生产级管理员认证、备份和监控。

本文中的“代理登录”“完成注册”和“有效认证”，除非明确标注为人工模式，均指不访问 SiliconFlow 的 mock 演示。

## 角色与入口

| 角色 | 页面入口 | 当前可做的事情 |
|---|---|---|
| 管理员 | 首页的“订单管理” | 创建订单、复制链接、人工确认认证、登记支付宝转账结果 |
| 淘宝客户 | 管理员生成的客户订单链接 | 使用 mock 获取邀请码，或手动填写邀请码/官方邀请链接并开放任务 |
| 抢单人 | 首页“任务大厅”或任务链接 | 手机号登录、登记支付宝、抢单、查看倒计时并模拟完成任务 |

## 启动本地系统

### 环境要求

- Windows PowerShell，或 Linux/macOS Bash；
- 已安装可从命令行调用的 Python；
- 首次运行可访问 Python 软件包源；
- 已进入克隆仓库的 `mvp` 目录。

### 启动步骤

打开 PowerShell，执行：

```powershell
cd <仓库目录>\mvp
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

首次启动会在 `mvp\.venv` 创建 Python 虚拟环境并安装依赖。看到 Uvicorn 启动信息后，在浏览器打开：

<http://127.0.0.1:8765>

也可以访问 <http://127.0.0.1:8765/api/health> 检查服务状态。停止服务时，在运行窗口按 `Ctrl+C`。

端口被占用时可改用：

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1 -Port 8766
```

开发验证码会在页面点击“获取验证码”后显示。管理员应使用启动环境中的 `MVP_ADMIN_KEY`；当前仓库已有本地演示配置说明，参见 `README.md`。任何演示值都不得复用于公网部署。

Linux/macOS 在 `mvp` 目录执行 `./run.sh`。端口通过环境变量调整，例如：

```bash
MVP_PORT=8766 ./run.sh
```

## 完整本地演示

建议使用三个浏览器窗口或无痕窗口分别扮演管理员、客户和抢单人。不要输入真实支付宝资料或其他生产数据。

### 1. 管理员创建订单

1. 打开首页，点击“订单管理”。
2. 输入本地开发环境的管理员密钥。
3. 在“创建付款订单”中填写一个未使用过的测试淘宝订单号。
4. 选择 SKU：`SF_INVITE_1`、`SF_INVITE_5` 或 `SF_INVITE_10`，分别代表每件 1、5、10 个完成名额。
5. 填写购买数量。目标人数等于 SKU 人数乘以购买数量。
6. 选择 SiliconFlow 模式：完整本地演示选择“本地代理登录演示”；只验证人工流程选择“人工邀请码”。
7. 点击“生成订单链接”，立即保存页面显示的客户订单链接和任务链接。

客户订单链接包含一次生成的随机令牌，数据库只保存其哈希值，之后无法从管理台恢复原始链接。若本地演示时遗失，应创建新的测试订单。

### 2. 客户配置邀请码

打开上一步的客户订单链接。当前有两条流程：

**Mock 代理登录演示**

1. 输入一个格式有效、仅用于测试的中国大陆手机号。
2. 点击“获取验证码”，页面会显示本地演示验证码，不会发送短信。
3. 填写该验证码并勾选授权说明。
4. 点击“获取邀请码”。系统生成合成的 8 位邀请码和邀请链接，并用合成会话验证 24 小时密文保存逻辑。

**手动邀请码流程**

1. 切换到“手动填写”。
2. 输入 8 位英文字母/数字邀请码，或格式为 `https://cloud.siliconflow.cn/i/XXXXXXXX` 的完整官方邀请链接。
3. 勾选信息提交确认，点击“确认邀请码”。

成功后订单状态变为“任务已开放”。复制任务链接，供下一步使用。当前系统不会自动把链接发送到淘宝聊天或微信群。

### 3. 抢单人登录并登记收款信息

1. 打开任务链接，或从首页“任务大厅”进入已开放任务。
2. 点击右上角“手机号登录”。
3. 输入一个仅用于测试、格式有效的中国大陆手机号，点击“获取验证码”。
4. 输入页面显示的开发验证码并登录。
5. 按页面提示登记支付宝账号和实名姓名。测试时使用虚构数据，不要填写真实收款资料。

同一登录账号或支付宝账号只能获得一次奖励；重复测试不同抢单人时，应使用不同的测试值。

### 4. 抢单并完成 Mock 任务

1. 在任务页点击“立即抢单”。
2. 抢单成功后，服务端开始计算 30 分钟保护期，页面显示倒计时。
3. 点击“模拟完成注册”，使当前记录进入已注册状态。
4. 点击“模拟完成有效认证”，使系统尝试锁定 5 元奖励。
5. 打开“我的任务”查看注册、认证和奖励状态；15 分钟提醒会显示在站内通知中。

Mock 按钮只在 `development` 环境出现，不能证明真人已经在 SiliconFlow 完成任何操作。

### 5. 人工确认流程

使用“人工邀请码”模式时，管理员可以在“订单管理”中对状态为保护中或已超时的抢单记录点击“人工确认”。系统要求输入一个用于去重的 SiliconFlow 账号 ID。

执行前必须由管理员在可信证据中核实该用户确实是新用户，并已填写指定邀请码和首次完成有效实名认证。当前系统不采集身份证、人脸或证件照片，也不会自动完成这项核验。

### 6. 登记人工支付宝转账

任务成功且奖励被锁定后：

1. 管理员在支付宝外部完成 5 元人工转账。
2. 回到“订单管理”的“待支付奖励”。
3. 点击“登记已支付”，输入该笔真实转账的唯一流水号。
4. 确认状态变为“已支付”。

“登记已支付”不会发起转账。不得在尚未实际付款时提前登记，也不要重复使用同一流水号。

## 业务规则

- 订单有效期从创建/付款时间起计算 24 小时，登录和重试不会延长。
- 抢单后保护 30 分钟；到达截止时间即视为超时并释放保护名额。
- 保护中名额与已锁定奖励之和不会超过订单目标人数 N，没有候补队列。
- 超时用户在订单有效期内补做成功，只有订单仍未满额时才可获得奖励。
- 订单已满或已超过 24 小时时，补做不再获得奖励。
- 待支付、支付重试和已支付奖励均占用已完成名额，不会因尚未付款释放给其他人。
- 同一本站账号、支付宝账号和上游用户标识只能成功领取一次奖励。

## 模式选择

| 模式 | 用途 | 是否访问 SiliconFlow | 是否自动判定真实状态 |
|---|---|---:|---:|
| `mock` | 本地完整流程演示、自动化测试 | 否 | 否，仅合成状态 |
| `manual` | 客户手动填邀请码、管理员人工核实 | 否 | 否 |
| `live-disabled` | 验证生产默认失败关闭 | 否 | 否 |

当前版本没有可启用的 live 模式。出现“真实 SiliconFlow 登录适配器尚未启用”属于预期保护行为。

## 数据与重置

- 本地数据保存在 `data\mvp.db`，重启服务不会清空。
- 启动时会补充演示订单，但不会覆盖已有订单。
- 需要全新测试库时，先停止服务，备份并移走 `data\mvp.db`，再重新启动。该操作会移除当前所有本地订单、用户、任务和奖励记录。
- `data\mvp.db` 可能包含加密后的测试资料和索引，不应提交 Git 或发送给他人。
- 客户订单链接和任务链接应按访问凭据处理，不要公开到非测试渠道。

## 常见问题

**页面打不开**  
确认运行 PowerShell 窗口仍在工作，并访问启动信息中的端口。若端口冲突，使用 `-Port` 参数启动。

**首次启动安装依赖失败**  
确认 Python 可用、网络可访问软件包源，并查看 PowerShell 中的第一条错误；不要只反复刷新浏览器。

**管理员密钥不正确**  
确认输入值与启动进程的 `MVP_ADMIN_KEY` 一致。修改环境变量后必须重启服务。

**淘宝订单号已存在**  
订单号具有唯一约束。为下一次演示使用新的测试订单号。

**无法抢单**  
依次确认已登录、已登记支付宝、任务处于开放状态、订单未到 24 小时截止时间且仍有可用名额。

**显示名额已满但完成数未满**  
保护中的抢单人也会占用容量。其 30 分钟保护期结束后，页面再次请求服务端状态才会显示释放结果。

**没有收到真实短信或没有同步淘宝/SiliconFlow 数据**  
这是当前版本的已知边界，不是本地配置错误。相关 live 接入尚未完成。

## 复验

停止正在运行的服务不是必须条件。另开 PowerShell，在项目目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\run-tests.ps1
```

当前基线应得到 16 项测试通过。外部技术验证在 `..\tech-validation` 目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\run-validation.ps1
```

Linux/macOS 使用：

```bash
./run-tests.sh
cd ../tech-validation
./run-validation.sh
```

测试只验证本地状态机、并发、安全边界和合成适配器，不等同于 SiliconFlow 或淘宝生产验收。
